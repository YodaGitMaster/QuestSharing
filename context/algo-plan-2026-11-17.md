## E1 — Stability rule that actually works (QuestOptimizer.lua, O.optimize)
- Today: keep `preferred` only if `preferred[1]==best[1] and preferred[2]==best[2]` and within `stabilitySeconds` — key 2 is `-time`, so only exact ties.
- New: keep the previous plan unless the new one hands in more quests (higher primary key) or saves at least `max(options.stabilitySeconds (default 12), 5 % of preferred.time)`. For `xp` mode compare XP/time with a 5 % relative margin. Report `report.keptPrevious = true` when kept.
- Tests: two near-equal routes (difference 4 s) never flip across repeated optimizes with the previous order as `preferredIDs`; a route 30 s better replaces it; more coverage always wins.

## E3 — Rolling horizon, beam removed (QuestOptimizer.lua)
- Local search moves only actions inside the first `options.horizon` positions (default 12 atoms ≈ 8 visible stops); the tail stays greedy/seeded. When `#path <= 16` the horizon covers the whole path (keeps tiny-route optimality tests meaningful).
- Delete `beamSearch` and its call; keep report fields `searchExhausted` (false unless the seed budget ran out) so callers/tests stay valid.
- Tests: improvement moves never change positions beyond the horizon (instrumented); CPU steps on a 50-quest synthetic zone drop vs today; the four-goal exhaustive-reference test and all existing goal tests still pass.

## E2 — Costs calibrated from real play (new QuestCalibration.lua + QuestPlanner.planOptions)
- Observe while the guide session is active, out of combat-lockdown-sensitive code (no protected calls):
  - **killSeconds**: interval between consecutive progress increments of the same kill/loot objective in the player's log (QUEST_LOG_UPDATE diff via existing log snapshot); ignore gaps > 90 s or < 1 s; one sample per increment step (an increment of n counts as n samples of gap/n).
  - **interactionSeconds**: time from the player coming within ~10 yd of a planned pickup/turn-in NPC point to the matching QUEST_ACCEPTED / QUEST_TURNED_IN; ignore > 60 s.
- Rolling median of the last 40 samples each, clamped (kill 4–40 s, interaction 1–15 s); require >= 5 samples before overriding the defaults (10 s / 3 s). Persist in `QuestSharingDB.plannerCalibration` (per character not needed). `/qs plan calibrate` prints values + sample counts; `/qs plan calibrate reset` clears.
- planOptions passes the calibrated values; `/qs plan why` / report shows "calibrated from N kills" or "default".
- Tests: progress ticks every 7 s -> killSeconds ≈ 7 after 5+ samples; outliers ignored; clamping; reset; persists across a simulated reload; planner uses the value (expectedSeconds changes accordingly); no work at login or with the guide closed.
