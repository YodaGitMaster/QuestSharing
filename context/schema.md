## Addon loading and persistence
- `QuestSharing/QuestSharing.toc`: Interface 16001, version 0.4.19; declares file load order and SavedVariables.
- Lua modules receive `local ADDON, ns = ...`; `ns` is the shared namespace, not a class.
- `Core.lua`: `ns.defaults`; `ns.db` initially copies defaults. On `ADDON_LOADED`, missing settings are filled and `ns.db` aliases saved `QuestSharingDB`; current `dbVersion = 3`.
- SavedVariables: `QuestSharingDB` (settings), `QuestSharingLog` (debug log); persisted by the game.
- `debug`: default true; `diagnosticsDefaultMigrated` enables recording once for existing installs, then preserves explicit off. Errors record independently of the switch.
- `ns.diagnosticOverview(checks?)`: plain-language numbered newest-first error summaries, last-seen/repeat counts, friendly blocked-feature names and setup/client notes separate from error counts. Only overview messages shorten to 220 bytes; full messages remain intact.
- `ns.diagnosticLines(checks?,overview?)`: overview + complete numbered error messages/stacks + doctor checks + one labelled defaults-backed setting per line + blockedFeatures + all retained log lines, with section headings and end marker. `/qs log`, `/qs errors`, `/qs doctor` and General use `ns.diagnostics(details?)`; open overview without text selection or chat dump.
- `QuestSharingReport` snapshot: `fullText`, `overviewText`, `showingDetails`, `kind`, optional `refreshAction`. Planner reports use `kind="planner"` and refresh through `P.debug`; Clear records appears only for diagnostics. `P.debugText()` reads the current catalog, route, report and last completed plan options without enumerating QuestieDB. Details toggle reads same snapshot; **Copy all** displays/selects `fullText` then player presses Ctrl+C/Cmd+C, regardless of initial view. Explicit Refresh preserves view, replaces snapshot; clear empties both lists and returns to overview. Ring tests keep their original report text and copy behavior, without overview toggle. Bounded storage unchanged: 30 errors/~3000 logs (300-line trim slack); no display truncation. Slash clear arguments retain separate-list semantics.
- Optional dependencies: Questie, QuestieDB, AnglerAtlas, AtlasLootClassic, AtlasLootContinued; game API differences handled by `ns.compat` in `Compat.lua`.

## Quest planner (2026-11-17)

- Local quest facts now retain `gates[] = {kind, choices[], satisfied?}` alongside the graph's chosen discovery parent. `kind` is `turnin`, `accepted`, or `active`; the optimizer checks every AND group and any choice within an OR group at pickup time. Selected-mode action discovery includes all local alternative parents.
- QuestieDB reputation fields are absolute faction points: `requiredMinRep={faction,value}` (inclusive), `requiredMaxRep={faction,value}` (exclusive), `reputationReward[faction]=signedPoints` summed from provider pairs. `Compat.plannerReputation` samples only referenced factions using `C_Reputation.GetFactionDataByID.currentStanding` or legacy `GetFactionInfoByID` value. Unknown values stay absent. A simulated hand-in applies its verified reward once.
- Profession fields are `requiredSkill={skillLineID,minimum}` and `requiredRanks[]` OR pairs. `Compat.plannerSkills` reads referenced Forever `C_SkillInfo.GetSkillLineInfoByID.rank` values; unsupported clients leave ranks unknown. Skills are static in the simulator because no verified quest skill reward is available.
- Optimizer `report.searchChecks` counts bounded alternative evaluations and `report.searchExhausted` states whether its budget stopped the small-plan beam. Beam width defaults to 20 (maximum 32); it runs for at most 40 atomic actions and always retains the feasible seeded incumbent. The all-goal eight-quest harness takes 4,013 checks without exhaustion. Separate eligible loot streams sharing a camp set `report.uncertain=true`; for exactly two streams `report.lootBounds[campKey]={lowerKills,upperKills}` uses max versus sum of their separate expectations. The additive value remains an estimate.
- `Compat.plannerInventory(itemIDs)` scans carried bags 0..equipped bag limit on explicit plan work, returning `{counts,freeSlots}` or nil when the API is absent. It reads only candidate item counts and never scans the bank. Empty slot capacity remains unknown if the client exposes no slots.
- `QuestOptimizer` state now carries `inventory,freeSlots,level,levelXP,nextLevelXP` from `planOptions`. A known loot target adds its required items after work. Explicit `quest.consumedItems` subtracts at hand-in and can block a competing hand-in. One known live XP threshold supports one level transition after a hand-in; further levels await actual API observations.
- One-level-gated quests are retained only when known local quest XP can reach the live threshold. They remain labelled as an estimated unlock until the character levels. The all-quests objective ranks equal completed coverage by estimated elapsed time.
- `questPlanner` remains default-off and explicit-open only. The session `goal={mode,selectedIDs,budgetSeconds}` and `P.levelScope="all"|"green-yellow"` control distinct scoring modes. No new SavedVariables.
- Zone discovery caches numeric IDs for two zones and projects only same-zone/verified descendants. `P.coverage()` returns ID-to-reason maps for external, unknown, blocked, repeatable, completed and filtered. Chains use a reverse-gate work queue and preserve signed AND/OR, active and accepted parent semantics. Future levels are deferred explicitly.
- `Questie.plannerQuest` includes `xp,repeatable,exclusiveTo,parentQuest,availableStartingWith,availableUntilCompleted,requiredMaxLevel,beforeAny,beforeAll,targets,starters,turnIns`. Target fields include `kind,creditID,itemID,required,countSource,have,progressVerified,objectiveText,dropRates[npcID],rateSources[npcID],sources,points`. DropDB outputs percentages, converted to probabilities exactly once.
- Each atomic stop belongs to one quest and has `id,key,kind,point,quests,questTasks,tasks,deps,objectives`, plus optional `alternatives[] = {point,sourceID,tasks,questTasks}` (other real camps of the same objective, max 3 from the planner, 6 sites in the optimizer). The optimizer returns a shallow copy with the chosen site's `point`, `site`, `tasks`, `questTasks` and `objectives[1].sourceID`; input stops are never mutated. Objective evidence has `questID,target,remaining,sourceID,shareable`. Pickups/work/hand-ins retain real dependencies. Only consecutive solved instructions are grouped for display.
- `ns.questOptimizer.optimize(catalog,stops,options)` (options add `maxImproveSteps` default 250000, 0 = off; `improveWindow` default 10) returns atomic order plus `improveMoves,improveSteps,improveExhausted,mode,expectedSeconds,travelSeconds,workSeconds,waitSeconds,expectedKills,expectedXP,coverage,plannedIDs,completedIDs,missingIDs,reasons,baselineSeconds,baselineComparable,uncertain,iterations`. Costs include travel callback, kill/interaction costs and relative availability times. All mode maximizes compatible coverage before elapsed time, selected mode includes dependency closure, XP ranks known quest XP/time, budget ranks hand-ins under expected-time limit.
- Shared work requires an exact source/camp and acceptance before the farm segment. One loot stream uses E[max(k,T_r)] with a binomial tail expression, multiple kill quotas use their max. Unknown rates/counts remain estimated, separate loot streams receive conservative separate costs.
- Cooperative search compares nearest baseline, waiting-aware order, shared-camp preparations, at most twelve terminal alternatives and prior order, capped at 36,000 alternative candidate checks. Prior feasible orders can survive improvements <=10 seconds. Live log capacity is enforced when exposed.
- Visible progress/level/bag/spell events reuse zone IDs. A visible-only three-second movement/speed check rebuilds after material displacement. Closing, master-off, invalid zone and generation changes cancel `quest-plan` and `quest-improve`. Planning uses straight-line travel only (decouple run 2026-11-17); SPF is never asked for walking costs. Explicit Follow (`Path.follow` → SPF `Navigate`) retains provider ownership of terrain guidance.
- Plan controls and slash commands expose goals/range/report and temporary 300-second camp waits. Direct arrow/numbered map stops consume the grouped current route.
- 2026-11-17 fix-all run: new optimizer options and planner state.
  - Optimizer option `preferredSites={[stop.key]=O.siteKey(point)}` (`"map/x%.5f/y%.5f"`). `lockSites` was removed in the decouple run.
  - `waitingAt[campKey]=expiry` now applies to alternatives too: `avoidBusyCamps(stop,now)` drops busy alternatives, promotes a free one, and otherwise picks the earliest-expiring camp and sets `availableAfter[stop.id]`. It returns `wait, narrowed`; `planOptions` returns a 4th value `forced={[stop.key]=true}` for narrowed stops.

  - `quest-improve` (DataWork priority `"idle"`) is cancelled by `P.cancelEstimate()`. The `quest-costs` job no longer exists.
  - `ns.questPlannerPath` = `{available(), follow(point,title,kind)}` only; no walking estimates.
