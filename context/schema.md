## Cooking and profession companion (2026-11-17)
- `ns.db.professionGuide`: boolean, default true for this explicitly requested integration; false hides native companion buttons, cancels/closes it and suppresses automatic opening/global ingredient hints. Manual `/qs cooking` or `/qs professions` re-enables it. Fishing-map preference remains independent.
- `ns.cookingReference`: `{build="1.60.1.70888",recipes={...},items={[id]={name,vendor}}}`; generated pinned MIT snapshot, 133 records / 229 item names.
- Recipe `{id=spellID,name,skill?,ingredients={{itemID,count},...},books={recipeItemID,...},sources={string,...},uncertain=bool,output?}`. Unknown learn skill is nil, never a yellow threshold. Data can include unavailable/obsolete spells; availability isn't promised.
- `ns.professionReference.professions`: 12 `{id=baseProfessionID,name,source,ranks={...}}` entries. Rank `{name,cap,skill,level,Alliance,Horde,method}`; level 0 renders "no character-level requirement listed". Secondary Expert uses books; Artisan Cooking/Fishing/First Aid uses quests at skill 225/character 35. Crafting Artisan skill 200/character 35; cap 300.
- `professionReference.fish[itemID].locations`: `{map,water,minSkill?,safeSkill?,note?}`; seven guide-backed examples. Effective skills include bonuses; nil renders unknown. `cookingSources[spellID]` supplements starter source gaps; `vendorPlaces[NPC name]` adds guide locality/faction strings.
- `ns.professions._learned()[spellID]`: session-only true=Known, false=Missing, nil=Unconfirmed. Only read own Cooking185; linked/guild/NPC/changing rejected. 12 IDs per timer slice; no native filters/recipe-ID enumeration. Combat pauses; close/disable/source switch invalidates generations.
- `P.materialLines(itemID)`: direct installed Questie drops/vendors and NPC min/max/spawns, static fish-water hints and optional AnglerAtlas zone estimates; no item-catalogue enumeration. Bounded displayed NPCs/locations, unknown labels and Refresh for late providers. Modern TooltipDataProcessor with guarded legacy hook fallback decorates ingredient IDs only, excluding recipe books.
- UI: 740x610 movable companion; Cooking/Upgrades tabs, six 26px-spaced recipe rows, All/Missing/Known filter, search, six ingredient buttons, scrollable source detail; upgrades show 12 profession buttons, four ranks and Both/Alliance/Horde selector. Native child button strip leaves Blizzard filters/tab manager untouched.

## Addon loading and persistence
- `QuestSharing/QuestSharing.toc`: Interface 16001, version 0.4.19; declares file load order and SavedVariables.
- Lua modules receive `local ADDON, ns = ...`; `ns` is the shared namespace, not a class.
- `Core.lua`: `ns.defaults`; `ns.db` initially copies defaults. On `ADDON_LOADED`, missing settings are filled and `ns.db` aliases saved `QuestSharingDB`; current `dbVersion = 3`.
- SavedVariables: `QuestSharingDB` (settings), `QuestSharingLog` (debug log); persisted by the game.
- Optional dependencies: Questie, QuestieDB, AnglerAtlas, AtlasLootClassic, AtlasLootContinued; game API differences handled by `ns.compat` in `Compat.lua`.

## Runtime shapes
- `Share.lua`: `ns.known[questID][lowercasedMemberName] = status`; `ns.offered[questID][lowercasedMemberName] = true` after an offer reaches a member.
- `Sync.lua`: addon channel messages separated by `|`; `H|1` hello, `L|i|n|entries` quest-list parts, `P|entry` quest update. Entry: `questID:complete(0/1):objectives`; consult encoder/parser before changing wire format.

## Quest planner (2026-11-17)
- `QuestSharingDB.questPlanner`: boolean, default `false`; enabling/opening the feature is opt-in. No new persisted route data.
- A plan is allowed only on an outdoor `Zone` map that is not a city. Each async batch rechecks the map; entering a town clears the plan, while changing outdoor zones restarts the scan. Stop selection and waypoint actions reject stale-zone plans.
- Questie exposes an enumerable quest-ID list rather than a zone-indexed list through this adapter. The planner checks IDs in shared DataWork slices on explicit open and retains locally completable pickups and local actions from active quests; it does not scan on login, while hidden, or in a city. `sessionActive` gates all event refreshes. `zoneQuestIDs[map]` retains numeric starter IDs for the last two discovered zones, including currently ineligible/completed quests; active log IDs are unioned on reuse. Explicit Refresh invalidates the zone ID entry. Projection accepts same-zone points or verified descendant maps only; finite 0..100 spawns and positive bounded parent rectangles required. Unrelated maps are rejected even if the native rectangle looks usable.
- `Questie.plannerQuest(id,sourceCache?)`: session projection `{id,name,level,requiredLevel,beforeAny[],beforeAll[],starters[],targets[],turnIns[]}`. Questie remains the read-only source; objective sources are uncapped for this projection. An optional per-scan 256-entry FIFO source cache keyed `kind:id` shares `{kind,id,name,spawns}` for repeated starters/targets/hand-ins. Item-start wrappers stay distinct so `startsFrom` cannot mutate shared sources. Planner field checkpoints cooperate with DataWork outside provider calls.
- The planner compares each quest level with `GetQuestDifficultyColor` and the game's `QuestDifficultyColors`; only `standard` (green) and `difficult` (yellow) enter the plan. Missing/unrecognized level color is excluded rather than guessed.
- `QuestCandidate`: projection plus `{status=active|ready|future,starterRows,starterPoint,entry,depth,prereqIDs,canFinishHere}`. New quests exclude pending targets without local locations or known remote-only hand-ins. Active quests require local unfinished work or a ready local hand-in. `canFinishHere` requires local locations for all pending targets and a local hand-in; future gates only use parents that can finish here or are already completed. Future candidates remain limited to four layers.
- `PlannerStop`: `{id,outingID,phase,kind=pickup|objective|turnin,point={map,x,y},quests,tasks,questTasks[questID][],destination?,deps}`. Pickup/turn-in text includes known giver; objective text includes matched progress. Stops merge only by same kind AND prerequisite depth (`phase`) AND geographic threshold: objectives <=0.065 normalized units, pickups/hand-ins <=0.045. This prevents both distant-camp grouping and future quests merging into earlier prerequisite stops. `questTasks` preserves per-quest instructions; `destination` is a giver/objective fallback when native point naming is unavailable.
- Stops connect into outings by quest chain, shared stop and prerequisite dependencies. Whole-outing order uses a nearest-neighbour map-distance estimate normalized for represented quest count; if SPF API v2.3+ is installed, `QuestPlannerPath` asynchronously compares dependency-ready outing starts with `EstimateWalks` and promotes the reachable outing with the lowest walking-yard cost. Later stops retain the existing dependency/map-distance order. This does not yet optimize every leg or infer unknown cave floors.
- Loot targets can show a Questie DropDB percentage when available; missing/unknown rate stays unshown. The current route score does not use drop chance or estimate kill time.
- UI is session-only: `/qs plan [refresh|next|on|off|hide|follow]`, settings action, scrollable tracker-side stop rows, native click-to-waypoint and optional **Follow with SPF**. SPF `Navigate` is called only on explicit follow action and owns the drawn route. Missing SPF leaves the existing waypoint flow intact. The panel opens only on explicit tool enable/open; login remains idle. While visible, changed zones trigger discovery/reuse, quest acceptance/removal/turn-in refreshes eligibility from cached local IDs plus active quests, and changed objective progress rebuilds stops through DataWork. Close/master disable cancels the worker; re-enable does not auto-open it. It never auto-accepts quests.
- Compact opaque dark guide header shows brand, options/help, session position Lock/Unlock, close, previous/next, current/total step, zone and mini/expanded toggle. Local `guideExpanded`/`guideLocked` are session-only. `P.navigate(+/-1)` rejects boundaries, revalidates zone and sets waypoint without completing quests. Render current step in gold/white on dark red and up to five muted upcoming steps; mini shows only current row and shrinks panel. Long rows retain measured height and scrolling; map tick/progress snapshots unchanged. Native guidance uses existing waypoint/SPF actions; no separate new compass engine.
- Each row is `Step N: Go to <known native place | giver | objective area>` plus coordinates, then Take/Complete/Hand-in instructions. Quest numbers are assigned by first route occurrence and remain consistent within that plan; all per-quest tasks shown, no four-task truncation. Left/right-click and footer Waypoint set waypoint; player opens map normally. Empty below-green state, session movement and measured row height remain. Loading/errors live in body rather than overflowing compact zone header.
- `tools/preview_quest_planner.py` executes real Lua planner in existing harness, navigates all eight illustrative sample stops and exports actual row strings/points into `tools/quest-guide-preview.html`. Output fragment carries no live character data or network calls. It mirrors core interactions for browser inspection; native font/layout/compositing remain game-specific.
- `QuestPlannerPath.lua`: accepts SPF API version 1 or 2 for `Navigate`; requires version 2/minor 3 and function presence for `EstimateWalks`. It validates normalized coordinates and same-map targets, chunks at 256, serializes async batches, cancels superseded work and ignores stale callbacks. Routes are not replaced unless the player uses Follow with SPF.
- `questLogState`: sorted active quest IDs, completion/objective-finished state, and have/need counts. Quest-list, completion flags or level changes rescan candidate eligibility; count-only progress rebuilds stops preserving selection. Zone-change events clear stale rows immediately before debounce; scan start cancels prior SPF estimates.
- `render` is forward-declared because async `scan` completion calls it; otherwise Lua binds the later local definition as a global at the earlier reference.
- The panel docks immediately left of `ObjectiveTrackerFrame`, `WatchFrame`, or `QuestWatchFrame` when available. `/qs plan hide` hides the panel without disabling the feature.
